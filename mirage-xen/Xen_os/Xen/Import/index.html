type t = {
  1. domid : int;
    (*

    foreign domain who is exporting memory

    *)
  2. ref : Gntref.t;
    (*

    id which identifies the specific export in the foreign domain

    *)
}

A foreign domain must explicitly "grant" us memory and send us the "reference". The pair of (foreign domain id, reference) uniquely identifies the block of memory. This pair ("grant") is transmitted to us out-of-band, usually either via xenstore during device setup or via a shared memory ring structure.

module Local_mapping : sig ... end
val map_exn : t -> writable:bool -> Local_mapping.t

map_exn grant ~writable creates a single mapping from grant that will be writable if writable is true.

val map : t -> writable:bool -> (Local_mapping.t, [> `Msg of string ]) Stdlib.result

Like the above but wraps the result in a result type instead of raising an exception.

val mapv_exn : t list -> writable:bool -> Local_mapping.t

mapv_exn grants ~writable creates a single contiguous mapping from a list of grants that will be writable if writable is true. Note the grant list can involve grants from multiple domains. If the mapping fails (because at least one grant fails to be mapped), then all grants are unmapped.

val mapv : t list -> writable:bool -> (Local_mapping.t, [> `Msg of string ]) Stdlib.result

Like the above but wraps the result in a result type instead of raising an exception.

val with_mapping : t -> writable:bool -> (Local_mapping.t -> 'a Lwt.t) -> ('a, [> `Msg of string ]) Stdlib.result Lwt.t

with_mapping grant ~writable f maps grant, calls f on the result, and then unmaps it. Returns Error _ if the map operation fails.

Copying without mapping

val copy_from : domid:int -> gref:Gntref.t -> src_off:int -> dst:Io_page.t -> dst_off:int -> len:int -> (unit, [> `Msg of string ]) Stdlib.result

copy_from ~domid ~gref ~src_off ~dst ~dst_off ~len asks the hypervisor to copy len bytes out of the page domid has granted as gref, starting at src_off, into dst at dst_off.

Unlike map_exn this touches no page tables, so it costs one hypercall and no TLB invalidation, which makes it the cheap way to move bulk data out of a foreign page. domid must have granted read access.

Xen names each endpoint as a frame plus an offset into it, which imposes two things. The local buffer must be page aligned, hence Io_page.t rather than a bare Cstruct.t: the type is private and everything that builds one aligns, so this cannot be got wrong. And one copy may not cross a page boundary, which no type can express; that is checked at run time and reported as Error. Transfers spanning several pages must therefore be issued a page at a time, which is what src_off, dst_off and len are for.

val copy_to : src:Io_page.t -> src_off:int -> domid:int -> gref:Gntref.t -> dst_off:int -> len:int -> (unit, [> `Msg of string ]) Stdlib.result

copy_to ~src ~src_off ~domid ~gref ~dst_off ~len is copy_from in the other direction: len bytes from src at src_off into the page domid has granted as gref, at dst_off. domid must have granted write access.

Only those len bytes reach the foreign page; the rest of it is left as it was. The same alignment and page-crossing rules as copy_from apply.
